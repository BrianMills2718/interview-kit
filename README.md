# interview-kit

Light planning, enforcement, skills and subagents for building agentic AI solutions with an AI
coding assistant. No claims, worktrees or coordination ceremony: plan first, small checked steps,
tests that could fail, a review pass, and a clear explanation.

## Built for

Timed take-home coding tests in a hosted browser IDE (verified in a CoderPad "Python Project":
terminal, internet, pip, git, Python 3.12). Typical rules: an agentic-AI problem, about 4 hours,
LangChain/LangGraph or raw API calls allowed, and **only the IDE's built-in AI chat** may be used
(CoderPad's has Ask, Plan and Edit modes; every prompt is recorded). Typical grading: completeness,
clarity and quality of the solution; how the AI is used; the explanations of the code. The kit
brings the method (notes, checks, roles), never another AI tool.

## Pull it in

**Hosted IDE with a terminal (e.g. a CoderPad Python Project):**

```bash
git clone --depth 1 <this repo's URL> kit   # copy the URL from the repo page's Code button
cp kit/PLAN.template.md PLAN.md
```

The `kit/` folder appears in the file explorer, so its files can be attached to the IDE's AI
chat as context. Add a Check button by adding this target to the project's `.cpad` file:

```json
"check": { "label": "Check", "command": "bash kit/check.sh" }
```

**No terminal or no internet:** open `KIT.md` on the repo page in another tab,
click Raw, and paste it into a `KIT.md` file. It holds every rule, the plan template, the skills and the
subagent roles in one file.

**Claude Code:** `/plugin marketplace add <owner>/interview-kit` (owner from the repo URL), then
`/plugin install interview-kit@interview-kit`. The skills and subagents load natively.

## Use it

Attach `kit/AGENTS.md` (or `KIT.md`) in the assistant and start with:

> Read AGENTS.md and follow it for this session. Act as the planner first: write PLAN.md.

Then step through: implementer for each step, `bash kit/check.sh` after each, tester to add
cases, reviewer before finishing, and `bash kit/check.sh --final` at the end.

## What is here

| File | Use it when |
|---|---|
| `AGENTS.md` | always: how the assistant works (plan, roles, small steps, checks, explain) |
| `PLAN.template.md` | start of every task: copy to `PLAN.md` and fill in |
| `check.sh` | after every step (`--final` at the end; `--install-hook` to run it on each commit) |
| `skills/using-ide-ai-chat/SKILL.md` | using the IDE's recorded AI chat well (start here) |
| `skills/plan/SKILL.md` | writing the plan |
| `skills/langgraph-agent/SKILL.md` | building a tool-calling agent or multi-step graph |
| `skills/evaluate-agent/SKILL.md` | testing an agent offline and evaluating it on known cases |
| `skills/explain-your-work/SKILL.md` | writing the README and code explanations |
| `skills/mcp-and-a2a/SKILL.md` | the task mentions MCP, tool servers, or agents talking to agents |
| `agents/planner.md`, `implementer.md`, `tester.md`, `reviewer.md` | the four roles |
| `examples/agent_template.py` | a runnable LangGraph agent to copy |
| `examples/patterns.py` | structured output, a retrieval tool, a human approval step (tested) |
| `examples/patterns_multi.py` | a supervisor with specialist agents as tools; streaming progress (tested) |
| `examples/mcp_server.py` | exposing a tool over MCP with the official SDK (tested) |
| `practice/PROBLEM.md` | a timed 2-hour rehearsal; `practice/grade.py` grades it |
| `KIT.md` | generated by `./build_kit.sh`: all notes in one file |
| `.claude-plugin/` | lets Claude Code install the kit as a plugin |

## Working on this repo (for agents improving the kit)

`AGENTS.md` is the rulebook for the assistant *inside a test*, not instructions for editing this
repo. To improve the kit:

- **This repo is public.** No company names, interview details, personal data or secrets.
- Keep notes short; `KIT.md` must stay small enough to paste.
- Test every code snippet offline with a fake model, like `tests/test_agent_template.py`.
- Before committing: `./build_kit.sh`, `uv run pytest -v` (all pass), `claude plugin validate .`.
- Commits need a plan: company-planning `cli.py skeleton` then `cli.py check` before `adopt`;
  tag commits `[Goal <plan_id>]`.

The [wiki](wiki/index.md) has the full map, the decisions, the evidence so far and the list of
next additions.
